# Provider 연결 상태 주기 점검 설계

## 목적

시스템 Provider 연결 중 `Active`인 연결만 설정된 주기에 따라 상태를 확인한다. 기본 주기는 60분이며, 모델 카탈로그 조회나 모델 선택을 자동으로 수행하지 않는다.

## 범위

- 시스템 관리자 설정 화면에서 상태 확인 주기를 조회·저장한다.
- 저장된 주기의 기본값은 60분이다.
- 백그라운드 작업은 `system_provider_connections.enabled = true`인 연결만 선택한다.
- 기존 Provider Adapter의 `verify` 경로를 사용하여 상태를 확인한다.
- 성공·실패 상태와 마지막 확인 시각을 연결에 기록한다.
- 실패한 연결도 다음 주기에 다시 확인하며, 한 연결의 실패가 다른 연결의 점검을 중단시키지 않는다.
- 모델 카탈로그 갱신, 논리 모델 변경, Credential 변경은 수행하지 않는다.

## 데이터·API

- Provider 상태 점검 주기는 시스템 전역 설정 테이블에 저장한다.
- 관리자 전용 same-origin API로 주기를 조회·수정한다.
- 허용 주기는 1분 이상 24시간 이하의 정수 분으로 제한한다.
- 기존 연결의 `verification_status`와 `verified_at`을 점검 결과로 갱신한다.

## 실행·종료

- API lifespan 시작 시 점검 루프를 시작한다.
- 설정된 주기마다 한 번 실행하고, 프로세스 종료 시 task를 취소하고 기다린다.
- 초기 기동 직후 즉시 Provider를 호출하지 않고 첫 점검은 60분 후에 수행한다.
- 외부 호출은 기존 Adapter timeout·redirect·credential 정책을 그대로 따른다.

## 검증

- 기본값이 60분인지 검증한다.
- 비활성 연결이 점검 대상에서 제외되는지 검증한다.
- 활성 연결은 성공·실패 결과가 기록되는지 검증한다.
- 한 연결의 실패가 다른 활성 연결 점검을 막지 않는지 검증한다.
- 설정 API와 UI가 same-origin 경계를 유지하는지 검증한다.
- 테스트용 연결·계정·기록은 테스트 완료 후 제거한다.

## 제외

- 모델 자동 조회
- Provider 모델 기본값 자동 변경
- 자동 활성화·비활성화
- Daon 자체 fallback 또는 재시도 정책 추가

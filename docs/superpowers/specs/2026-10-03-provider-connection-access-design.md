# Provider 연결 접근·모델 관리 설계

상태: 신산님 요구·구두 설계 확정(2026-10-03). 구현 대상은 Daon_User WSL 개발 환경이며 ysna/Oracle은 제외한다.

## 목표와 사용자 흐름

시스템 관리자가 Provider 연결과 사용할 모델을 관리하고, 일반 사용자는 관리자 설정을 변경하지 않은 채 허용된 모델만 사용한다. 관리자가 연결을 `공용 사용`으로 지정하면 모든 사용자가 사용할 수 있다. 비공용 연결은 사용자마다 자신의 Key를 등록하고 실제 연결 시험에 성공한 뒤 사용할 수 있다. `Ollama Public`처럼 Key가 필요 없는 연결은 항상 공용이다. 사용자는 `http://172.27.253.53:3330/`에서 실제 동작을 확인한다.

## 범위

- 관리자: Provider 이름 자유 입력, 연결 ID·이름·Endpoint·두 글자 고유 약어, 공용 여부, 인증정보, 사용 허용 모델, 실제 연결 시험 후 저장, 연결 삭제. 기존 연결과 신규 OpenAI 호환 API를 지원한다. 지원되지 않는 API 형식에는 성공 표시를 하지 않는다.
- 일반 사용자: 연결·허용 모델은 읽기 전용. 비공용 연결에서 본인 Key 등록·연결 시험·삭제만 가능하다. 공용 연결에는 자기 Key를 등록하지 않는다.
- UPSTAGE: `solar-pro4`만 선택·저장했다면 재조회 후에도 그 모델만 체크되며, 카탈로그에 다른 모델이 있어도 실행에 쓰이지 않는다.
- Provider 배지는 연결마다 고유한 대문자 영문 두 글자. 기존 `OPENROUTER`는 `OR`. 같은 Provider의 여러 연결도 서로 다른 약어를 사용한다.
- 미포함: 라이선스, ysna/Oracle 배포, 비 OpenAI 호환 신규 프로토콜, 임베딩/RAG 연결 재설계, 기존 Secret 교체.

## 상태와 권한

| 연결 종류 | 관리자 검증 | 사용자 화면 | 실제 인증 |
| --- | --- | --- | --- |
| Key 불필요·공용 | Endpoint 시험 성공 후 활성 | 모두 사용 가능 | Key 없음 |
| Key 필요·공용 | 관리자 Key 시험 성공 후 활성 | 모두 사용 가능 | 관리자 Key |
| Key 필요·비공용 | 관리자 설정은 사용 대기로 저장 | 해당 사용자 Key 시험 전 사용 대기, 성공 후 해당 사용자만 사용 가능 | 해당 사용자 Key만 |

`공용 사용`은 Key 존재 여부와 독립된 명시적 정책이다. Key 불필요 연결은 비공용으로 바꿀 수 없다. 비공용 연결에는 시스템 Key fallback이 없다. 사용자 Key 등록·검증·삭제는 서버에서 인증 사용자 ID로 제한한다. 일반 사용자 또는 Workspace 관리자의 직접 API 호출로도 연결 설정·허용 모델·공용 정책은 바꾸지 못한다.

## 저장과 검증

공용 연결 생성·Key/Endpoint 수정에는 비생성 probe를 먼저 수행한다. 실패하면 기존 설정을 변경하지 않고 안전한 오류 코드만 반환한다. 비공용 연결은 관리자 Key 없이 `사용 대기` 설정을 저장할 수 있으나 사용자 Key 검증 전 사용 불가다. 사용자의 Key 저장은 동일한 Adapter의 실제 비생성 probe 성공을 요구한다. UI 성공 문구와 `verification_status`는 probe 결과와 일치해야 한다. 비밀값·Upstream 응답 원문은 UI 응답, 로그, 감사 정보에 포함하지 않는다.

새 Provider 이름은 자유 입력한다. 실제 통신 방식은 지원 Adapter 또는 OpenAI 호환 API로 제한한다. 서버는 Endpoint allowlist/egress 정책, scheme, 사설 주소 접근 규칙을 기존 정책에 맞춰 검증한다. 브라우저는 same-origin BFF만 호출한다.

## 데이터와 모델

기존 연결·Credential·카탈로그·Workspace 기본 모델을 보존하는 additive migration을 만든다. 연결에 인증 유형, 공용 여부, 고유 약어와 Adapter 유형을 저장하고, 카탈로그의 전체 모델과 관리자가 허용한 모델을 별도 상태로 관리한다. 기존 연결은 기존 접근 동작을 유지하도록 migration에서 backfill한다. 두 글자 약어가 충돌하면 검증 가능한 결정적 배정으로 해소하며 `OR` 예약을 보장한다.

모델 선택 저장·재조회는 관리자 허용 목록을 기준으로 한다. 허용 목록이 비어 있으면 아무 모델도 사용하지 못한다. 기본 모델이 허용 목록에서 빠지는 수정은 충돌 오류로 거부하고 관리자에게 기존 기본값을 먼저 변경하게 한다. 모델 목록 자동 조회는 관리자 허용 목록을 암묵적으로 넓히지 않는다. 실행 resolver·카탈로그 API·Workspace 기본값 API는 모두 허용 목록과 연결 접근 정책을 적용한다.

## 삭제·보존

관리자 `연결 삭제`와 `시스템 Key 삭제`는 별개다. 사용자의 Key나 Workspace 기본 모델 등 참조가 있으면 연결 삭제를 차단하고 참조 종류·건수를 알려준다. 참조가 없을 때만 연결 행을 실제 제거한다. Key, 모델, 연결 변경은 version, idempotency, 감사 계약을 유지한다. 기존 dirty checkout과 `secrets/`는 보존한다.

2026-10-03 신산님 테스트 중 직접 수정 지시: Provider 관리 화면에서는 로그인된 시스템 관리자에게 비밀번호 재입력을 요구하지 않는다. 서버도 해당 Provider 관리자 API에서 별도 step-up 증표를 요구하지 않되, 서버의 시스템 관리자 권한 검사, 삭제 확인, version/idempotency 및 참조 삭제 차단은 유지한다. 다른 기능의 step-up 정책은 변경하지 않는다.

## 화면과 검증

관리자 화면은 목록/상세에서 공용 여부·Key 필요 여부·검증 상태·허용 모델을 분명히 표시하고, 연결 시험→저장 순서와 삭제 확인을 제공한다. 사용자 화면은 같은 연결을 읽기 전용으로 보여주고 비공용 연결의 본인 Key 상태와 시험 action만 제공한다. 본문·폼 최소 12px, 충분한 대비, 키보드 focus, 상태 문구, 1920×1080·1440×900·430×844 검증은 PMO 제품 디자인 표준을 따른다.

단위·API·DB migration·브라우저 테스트에서 관리자/일반 사용자 권한, 공용/비공용/무인증 상태, 실패 probe 불변성, UPSTAGE 단일 모델, 약어 중복, 참조 삭제 차단을 검증한다. WSL 개발 DB 사전 백업·migration preflight와 rollback 경로를 확인하고, 검증된 Git exact SHA로 WSL의 격리 checkout에서 빌드·기동한다. 기존 WSL checkout과 Secret은 덮어쓰지 않는다. 주소의 실제 로그인/관리자/일반 사용자 클릭과 브라우저 Network same-origin 확인 후 완료를 판정한다.

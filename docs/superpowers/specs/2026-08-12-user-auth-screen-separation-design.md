# 사용자 인증 3화면 분리 설계

상태: APPROVED — 2026-08-13 신산님 확정

## 목적

한 화면에 로그인·가입·인증·재설정을 함께 노출하지 않는다. 사용 목적을 `로그인`, `가입 및 이메일 인증`, `비밀번호 재설정`의 세 흐름으로 분리하고 각 흐름 안에서도 현재 단계에 필요한 입력과 동작만 표시한다.

## 사용자 흐름

### 로그인

- 최초 진입 화면이며 `사용자 ID`, `비밀번호`, `로그인`만 주요 입력·동작으로 제공한다.
- `가입하기`, `비밀번호를 잊으셨나요?` 링크로 다른 화면에 진입한다.
- 가입·인증·재전송·재설정 입력과 버튼은 로그인 DOM에 존재하지 않는다.

### 가입 및 이메일 인증

- 가입 단계는 `사용자 ID`, `메일 주소`, `비밀번호`, `가입`만 표시한다.
- 가입 성공 뒤 이메일 인증 단계로 전환해 인증 토큰, `이메일 인증`, `인증 재전송`만 표시한다.
- 완료 또는 `로그인으로 돌아가기`로 로그인 화면에 복귀한다.

### 비밀번호 재설정

- 요청 단계는 `사용자 ID 또는 메일 주소`, `재설정 메일 요청`만 표시한다.
- 요청 성공 뒤 설정 단계로 전환해 재설정 토큰, 새 비밀번호, `비밀번호 재설정`만 표시한다.
- 완료 또는 `로그인으로 돌아가기`로 로그인 화면에 복귀한다.
- 로그인 후 기존 비밀번호를 알고 바꾸는 `비밀번호 변경`은 계정 설정의 별도 기능이며 본 범위가 아니다.

## 보안·상태 계약

- Password와 Token은 Storage·Log·URL에 기록하지 않는다.
- 화면·단계 전환 및 요청 종료 시 Password와 Token을 즉시 지운다.
- 요청 중 현재 화면 버튼을 비활성화해 중복 제출을 막는다.
- 오류는 Safe Error만 표시하고 원문·내부 URL·Stack을 반사하지 않는다.
- 기존 same-origin `/bff/api/auth/*`, API DTO, Cookie/CSRF, Workspace redirect 의미를 유지한다.

## 화면 기준

- 1920×1080, 본문·폼 12px, 제목 16px를 유지한다.
- 설명은 도움말 아이콘·Tooltip으로 처리한다.
- 첫 입력 focus, Tab/Enter, `aria-labelledby`, `role=status`를 유지한다.

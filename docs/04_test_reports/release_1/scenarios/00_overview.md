## 시나리오 표기 규칙

각 시나리오는 다음 열을 가진다.

| 열 | 의미 |
| --- | --- |
| ID | `TS-<영역>-<3자리>` · 결함 보고와 추적표에서 이 ID를 참조한다 |
| P·수준 | 우선순위(P1~P3)와 필요 증거 수준(L1~L4, 테스트 계획 §4) |
| 절차 | 실행 단계. 화면 조작 문구는 M2 승인 후 구체화한다 |
| 기대 결과 | 합격 판정 기준 |
| 조항 | 근거 설계 조항(§) 또는 불변 조건 번호(INV-#, 작업계획 §6) |

우선순위 기준:

- **P1**: 불변 조건·보안·데이터 보호 위반 검출용. 실패 시 S1/S2 결함.
- **P2**: 필수 여정과 주요 기능 정확성.
- **P3**: 보조 기능·표시·경계값.

미확정 표식:

- `[M0]` — M0 결정(R1-D001~012) 확정 후 값·대상을 채움
- `[M2]` — G2-UX 승인 후 화면 조작 단계를 구체화
- `[API]` — OpenAPI 확정 후 오류 Code·필드명을 확정
- `[설계]` — 설계서 보완이 필요한 사항. 어울1 회부 대상 (Q·N 번호는 아래 질의 목록과 `release_1_design_queries.md`)

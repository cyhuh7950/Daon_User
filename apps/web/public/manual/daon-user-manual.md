# Daon 사용자 설명서

- Release: 1.0.0
- 문서 업데이트: 2026-09-17
- 언어: 한국어(ko-KR)
- 대상: 일반 사용자, 검토자, 승인자, Workspace 관리자, 시스템 관리자, 운영 담당자
- 범위: Web 중심의 현재 기능과 Windows·Mobile·Evidence Hub의 지원 경계를 설명합니다.

> Daon은 현재 Session과 Workspace 권한에 따라 보이는 화면과 사용할 수 있는 동작이 달라집니다. 이 설명서에 있는 메뉴가 보이지 않으면 먼저 현재 역할과 Workspace 권한을 확인하세요.

## 1. 목적과 설명서 사용 방법

처음 사용하는 경우 `Daon Getting Started`를 먼저 따라 한 뒤 이 설명서를 기능별 참고서로 사용합니다. 지식 Source와 모델 운영의 기술적 제한은 `Daon 지식·LLM 활용 가이드`에서 확인합니다.

각 절차는 다음 원칙으로 작성되었습니다.

- 화면에 표시된 실제 메뉴 이름을 사용합니다.
- 사용할 수 있는 기능과 연결 준비가 필요한 기능을 구분합니다.
- 성공 조건과 오류 대응을 함께 설명합니다.
- 비밀번호, Token, API Key, 내부 주소를 기록하거나 공유하도록 안내하지 않습니다.

## 2. 접근 경로와 제품·플랫폼 구성

공개 범위는 로그인·가입과 공개 설명서입니다. Notebook과 Workspace의 Source, 질문, Citation, Studio, Provider·라이선스 정보는 로그인 후 보호 범위입니다.

### 2.1 Web

현재 일반 사용자의 기본 업무 경로입니다. 로그인, Notebook 홈, Source 등록, 질문·Citation, Studio, 설정과 로그아웃을 제공합니다.

### 2.2 Windows Desktop

Windows 앱은 Web Workspace와 공통 화면을 사용하면서 로컬 Source와 오프라인 작업, Cloud 재연결·동기화 경계를 가집니다. 로컬에서 만든 작업을 Cloud로 전송할 때는 Preview와 명시적 승인이 필요합니다. Windows 앱의 설치 파일 제공 여부와 현재 배포 버전은 운영 담당자에게 확인합니다.

### 2.3 Android·iOS Mobile

저장소에는 Mobile Shell, Native Navigation, 권한 처리와 화면 계약이 있습니다. 모바일에서 허용되는 간단한 편집·검토 동작과 Web·Windows에서 계속해야 하는 고급 편집 경계도 정의되어 있습니다. 다만 현재 Release의 실제 설치, 로그인, 공개 API 연결과 실기기 전체 기능 검증은 완료된 것으로 보지 않습니다. 따라서 Mobile은 조직이 별도로 검증한 빌드를 제공한 경우에만 사용합니다.

### 2.4 Evidence Hub

Evidence Hub는 Web·Windows·Android·iOS의 검증 증거와 상태를 추적하기 위한 내부 개발·검증 도구입니다. 일반 사용자가 Notebook 작업이나 승인을 수행하는 제품 화면이 아닙니다. Hub에 `prototype_fixture` 또는 `deferred_actual`이 표시된 항목은 실제 사용자 기능 완료 증거로 해석하지 않습니다.

## 3. Workspace와 사용자 역할

현재 제품에서 사용자가 작업을 공유하는 경계는 Workspace입니다. tenant와 organization은 미래 확장을 위한 내부 호환 개념이며 현재 가입·관리 절차가 아닙니다.

- Workspace: 접근 권한과 작업 범위를 묶습니다.
- Notebook: 한 Workspace 안의 개별 작업 단위입니다.
- Source: Notebook에서 질문과 생성의 근거로 선택하는 자료입니다.
- Studio: 선택한 Source와 설정을 사용해 Notebook 안에 산출물과 Version을 만듭니다.

공동 작업 권한은 서버에 활성 Workspace 권한이 실제로 부여된 경우에만 적용됩니다. 다음 항목은 Workspace 내부 권한 모델이며, 현재 화면에서 각 역할이나 정책을 직접 설정할 수 있다는 뜻은 아닙니다.

- Workspace 관리자: 서버 권한 모델에서 보기, 질문, 분석, 생성, 편집, 검토, 수정 요청과 Workspace 내부 정책·멤버 권한 관리 권한을 가집니다.
- 편집자: 보기, 질문, 분석, 생성과 편집을 수행합니다.
- 검토자: 보기, 질문, 분석, 검토와 수정 요청을 수행합니다.
- 승인자: 보기, 질문, 분석, 검토, 승인, 전달과 생산 지식 등록을 수행합니다.
- 열람자: 보기만 수행합니다.

Workspace 역할은 시스템 관리자 여부와 별개입니다. 이 Release에는 공동 작업자를 초대하거나 Workspace 권한을 변경하거나 정책을 편집하는 사용자 화면이 없습니다. 따라서 Workspace 관리자 역할만으로는 `사용자 관리` 메뉴나 `/admin`을 사용할 수 없습니다. 서버는 Notebook, Source, Citation, Studio 산출물마다 현재 Workspace와 활성 권한을 다시 검사하며, 역할 이름만으로 다른 Workspace에 접근할 수 없습니다.

시스템 관리자는 Workspace 내부 역할이 아니라 전체 계정 운영을 위한 별도 보호 권한입니다. 시스템 관리자만 `사용자 관리`와 `/admin`에서 전체 계정을 검색하고 일반 사용자를 중지하거나 재활성화할 수 있습니다. 이 동작은 Workspace 멤버 초대나 역할 변경이 아닙니다.

## 4. 조작: 계정과 인증

### 4.1 가입

1. 로그인 화면에서 `가입하기`를 선택합니다.
2. 사용자 ID, 메일 주소와 12자 이상의 비밀번호를 입력합니다.
3. `가입`을 선택합니다.
4. 메일로 받은 인증 토큰을 입력합니다.
5. `이메일 인증`을 선택합니다.

인증을 완료하지 않은 계정은 로그인할 수 없습니다. 인증 메일이 오지 않으면 `인증 재전송`을 사용합니다.

### 4.2 로그인

1. 사용자 ID와 비밀번호를 입력합니다.
2. `로그인`을 선택합니다.
3. 현재 계정에 Workspace가 있으면 Notebook 홈으로 이동합니다.

인증되지 않은 사용자가 Notebook URL을 직접 입력했을 때 Notebook 내용이 표시되면 정상 동작이 아닙니다. 즉시 로그아웃 또는 브라우저 종료 후 운영 담당자에게 알립니다.

### 4.3 보호된 초기 시스템 관리자 로그인

보호된 초기 시스템 관리자 계정의 로그인 ID는 `admin`이며 이메일은 없습니다. 이 계정은 삭제하거나 중지할 수 없습니다. 최초 시작 또는 운영자가 서버 콘솔에서 초기화한 직후에만 `admin/admin`으로 로그인합니다.

1. 로그인 화면의 `사용자 ID`에 `admin`, `비밀번호`에 초기 비밀번호를 입력합니다.
2. `로그인`을 선택합니다.
3. `/password-change`의 `새 비밀번호 설정` 화면으로 이동하는지 확인합니다.
4. `현재 비밀번호`, 12자 이상의 `새 비밀번호`, `새 비밀번호 확인`을 입력합니다.
5. `비밀번호 변경`을 선택합니다.
6. 로그인 화면으로 돌아오면 새 비밀번호로 다시 로그인합니다.

강제 변경 전에는 Notebook 데이터가 보이지 않습니다. Session 조회, 현재 비밀번호 변경과 로그아웃 이외의 제품 요청은 HTTP 403 `PASSWORD_CHANGE_REQUIRED`로 거부됩니다. 비밀번호 변경 성공 직후 모든 기존 Session과 refresh family가 폐기되고 `admin/admin`은 즉시 무효가 됩니다.

### 4.4 비밀번호 재설정

`비밀번호를 잊으셨나요?`에서 사용자 ID 또는 메일 주소로 재설정 메일을 요청합니다. 받은 재설정 토큰과 새 비밀번호를 입력한 뒤 다시 로그인합니다.

이메일이 없는 보호 admin은 메일 재설정을 사용할 수 없습니다. 운영 담당자는 `4.5 admin 서버 콘솔 복구`를 따릅니다.

### 4.5 admin 서버 콘솔 복구

보호 admin의 비밀번호를 잊었다면 운영자가 현재 API 컨테이너의 서버 콘솔에서만 복구합니다. Web 화면이나 API에는 초기화 기능이 없습니다.

1. 승인된 배포 절차로 현재 API 컨테이너의 서버 콘솔에 접속합니다.
2. API Runtime과 같은 환경 및 데이터베이스 접근 권한이 준비되었는지 확인합니다. 내부 실제 서버 경로, DSN, Secret 값은 문서·명령 출력·문의 글에 기록하지 않습니다.
3. 프로젝트 명령 `python -m daon_user_api.admin_cli reset-initial-password`를 정확히 한 번 실행합니다.
4. 성공 메시지 `INITIAL_ADMIN_PASSWORD_RESET`과 종료 코드 0을 확인합니다. Runtime 실패는 `INITIAL_ADMIN_PASSWORD_RESET_FAILED:<오류 코드>`를 표시하고 종료 코드 1로 끝납니다. 잘못된 인자나 지원하지 않는 옵션은 명령 사용법인 `usage:`를 표시하고 종료 코드 2로 끝납니다. 명령은 비밀번호, hash 또는 token을 출력하지 않습니다.
5. 성공하면 admin의 모든 기존 Session과 refresh family가 폐기됩니다. 브라우저에서 `admin/admin`으로 다시 로그인하고 `/password-change`에서 즉시 새 비밀번호를 설정합니다.

명령은 고정된 보호 admin만 대상으로 하며 사용자 ID나 비밀번호 인자를 받지 않습니다. 실패 시 오류 코드를 운영 기록에 남기되 민감한 Runtime 설정을 함께 남기지 말고, 원인을 확인하기 전 반복 실행하지 않습니다.

### 4.6 Step-up 추가 인증

라이선스 적용, 동기화 승인 등 민감한 동작은 현재 비밀번호를 다시 요구할 수 있습니다. Step-up 입력값은 해당 승인 확인에만 사용되며 저장되거나 다시 표시되어서는 안 됩니다.

### 4.7 Session 만료

Session이 만료되면 보호된 Source, 질문, Citation과 산출물은 숨겨지고 다시 로그인해야 합니다. 입력 중 Session이 만료되면 같은 동작을 반복하기 전에 로그인 상태와 저장 여부를 확인합니다.

### 4.8 로그아웃

1. Notebook 홈 또는 Workspace에서 `설정`을 엽니다.
2. `로그아웃`을 선택합니다.
3. 로그인 화면으로 이동했는지 확인합니다.
4. `/notebooks` 주소를 직접 열어 보호된 내용이 다시 보이지 않는지 확인합니다.

로그아웃은 현재 Session을 종료합니다. 저장된 Notebook이나 Source를 삭제하지 않습니다.

## 5. 시스템 관리자 사용자 관리

`사용자 관리`는 로그인된 시스템 관리자에게만 Notebook 홈의 `설정` 메뉴에 표시됩니다.

### 5.1 사용자 찾기와 상태 확인

1. `설정 → 사용자 관리`를 선택해 `/admin`으로 이동합니다.
2. `사용자 목록`이 표시되는지 확인합니다.
3. 각 사용자 행에서 등록 이메일 주소 전체를 확인합니다. 이메일 미등록 계정은 `이메일 없음`으로 표시됩니다.
4. `사용자 검색`에 로그인 ID, 사용자 ID 또는 이메일을 입력합니다.
5. `상태 필터`에서 `전체`, `활성`, `중지` 중 하나를 선택합니다.
6. 각 행에서 `활성 계정`, `중지된 계정` 또는 `이메일 인증 대기`를 확인합니다.

검색은 현재 불러온 목록의 로그인 ID, 사용자 ID와 이메일을 대상으로 합니다. 등록 이메일 주소 전체는 로그인된 시스템 관리자의 `/admin` 사용자 목록에서만 표시되며 일반 사용자와 다른 화면에는 노출되지 않습니다. 계정의 비밀번호, hash와 token은 표시하지 않습니다. `이메일 인증 대기` 계정은 읽기 전용이므로 상태 변경을 할 수 없습니다.

### 5.2 일반 사용자 중지와 재활성화

1. 중지할 일반 사용자의 로그인 ID와 사용자 ID를 확인합니다.
2. `중지`를 선택합니다.
3. 행이 `중지된 계정`으로 바뀌고 버튼이 `재활성화`로 바뀌는지 확인합니다.
4. 다시 사용할 수 있게 하려면 `재활성화`를 선택합니다.
5. 행이 `활성 계정`으로 돌아오는지 확인합니다.

일반 사용자를 중지하면 그 사용자의 기존 Session이 폐기됩니다. 재활성화한 뒤에는 사용자가 자신의 정상 비밀번호로 다시 로그인해야 합니다. 사용자 관리 화면은 계정 삭제나 비밀번호 열람·직접 지정을 제공하지 않습니다.

### 5.3 보호 admin과 일반 사용자 접근 제한

초기 admin 행에는 `이메일 없음`, `보호된 시스템 관리자`, `보호됨`이 표시되고 상태 변경 버튼이 비활성화됩니다. 보호된 admin의 중지 요청은 HTTP 409 `PROTECTED_ADMIN_ACCOUNT`로 거부됩니다. 보호 admin은 삭제 및 중지할 수 없습니다.

일반 사용자는 `사용자 관리` 메뉴를 볼 수 없습니다. 일반 사용자가 `/admin`에 직접 접근하거나 관리자 API를 호출하면 HTTP 403 `FORBIDDEN`으로 거부되며 사용자 목록이 먼저 표시되지 않습니다.

## 6. Notebook 홈

### 6.1 Notebook 찾기

- 제목 일부를 `Notebook 제목 검색`에 입력합니다.
- `최근 수정`을 선택하면 최근 변경 순으로 정렬합니다.
- `제목`을 선택하면 제목 순으로 정렬합니다.
- Grid/List 버튼으로 보기 방식을 전환합니다.

검색 결과가 없으면 Notebook이 삭제된 것으로 단정하지 말고 검색어를 지워 전체 목록을 다시 확인합니다.

### 6.2 Notebook 만들기

1. `새 Notebook`을 선택합니다.
2. 제목을 입력합니다. 최대 120자입니다.
3. 선택 설명을 입력합니다. 최대 500자입니다.
4. 생성 동작을 완료합니다.
5. 빈 3열 Workspace가 열리는지 확인합니다.

### 6.3 기존 Notebook 열기

Notebook 카드를 선택합니다. 서버가 현재 Session과 Workspace 권한을 다시 검사한 뒤 해당 Notebook을 엽니다. 이전에 열었던 Notebook이 자동으로 권한을 우회해 열려서는 안 됩니다.

### 6.4 Notebook 영구 삭제

1. 삭제할 Notebook 카드의 `⋮` 메뉴를 엽니다.
2. `노트북 삭제`를 선택합니다.
3. 표시된 Notebook 제목을 확인 입력란에 똑같이 입력합니다.
4. `영구 삭제`를 선택합니다.

이 동작은 복구를 전제로 하지 않습니다. 다른 Notebook을 선택하지 않았는지 확인하고, 필요한 산출물을 먼저 내보냅니다. 삭제 중 오류가 나면 반복 클릭하지 말고 현재 목록을 새로 확인합니다.

## 7. Workspace 공통 화면

### 7.1 왼쪽: Source·지식·권위

다음 그룹을 표시합니다.

- `Daon 승인 지식`: Daon 2, Daon 2.5, Daon 3에서 등록된 지식 패키지
- `연결형 Source`: MCP와 기타 Connector를 통해 연결된 Source
- `Raw Source`: 사용자가 직접 등록한 파일 또는 텍스트
- 삭제 요청 Source 목록: 삭제 진행 상태가 있는 항목

### 7.2 가운데: 대화·실행

Source 또는 승인 지식을 선택하면 근거 질문을 실행합니다. 선택하지 않으면 인사·도움말 같은 제한된 작업 상담만 허용됩니다.

### 7.3 오른쪽: 업무 Studio

산출물 유형 선택, 생성 설정, 생성, Library, Version 수정, 검토·승인, 내보내기와 전달을 제공합니다.

### 7.4 화면 상태

- `불러오는 중`: 서버 응답을 기다립니다.
- `표시할 자료 없음`: 정상적으로 비어 있습니다.
- `준비됨` 또는 `사용 가능`: 다음 동작을 할 수 있습니다.
- `주의 필요`: 일부 기능에 확인이 필요합니다.
- `오류`: 요청이 완료되지 않았습니다.
- `접근 금지`: 현재 역할이나 Workspace 범위가 맞지 않습니다.
- `연결 전` 또는 `사용 불가`: 실제 Adapter, 서버 또는 Provider가 준비되지 않았습니다.

빈 상태와 오류 상태를 혼동하지 마세요. 빈 상태에서는 새 자료를 만들 수 있지만 오류 상태에서는 먼저 원인을 확인해야 합니다.

## 8. Source 관리

### 8.1 Source 추가 메뉴

`Source 추가`에는 `파일 업로드`, `웹사이트`, `Drive`, `복사한 텍스트`, `MCP 연결`이 있습니다.

### 8.2 파일 업로드

선택 가능한 확장자는 PDF, DOCX, PPTX, XLSX, CSV, TXT, MD, PNG, JPG/JPEG, M4A, WAV, MP3입니다. 선택 가능하다는 것은 등록 계약이 있다는 뜻이며 모든 형식의 의미 분석 완료를 뜻하지 않습니다.

현재 운영 사용은 PDF를 우선합니다. PDF는 페이지 단위 Citation과 질문 경로를 확인할 수 있습니다. 다른 형식은 조직이 해당 Adapter와 모델을 검증한 경우에만 업무 근거로 사용합니다.

### 8.3 복사한 텍스트

텍스트를 붙여 넣고 `텍스트 등록`을 선택합니다. 붙여 넣기 전에 개인정보, 비밀정보와 외부 전송 제한을 확인합니다.

### 8.4 웹사이트·Drive

Connector가 없으면 `연결 준비 필요` 상태가 표시됩니다. 사용자가 내부 주소를 직접 입력하거나 우회 연결을 만들지 않습니다.

### 8.5 MCP

현재 화면에는 국가법령정보센터 MCP 등록 흐름이 있습니다. 등록 후 연결형 Source에서 연결 상태와 Source 수를 확인합니다. 재연결은 기존 연결이 끊긴 경우에만 사용합니다.

### 8.6 Source 처리 상태

`등록됨 → 보안 확인 중 → 처리 중 → 색인 중 → 사용 가능`이 정상적인 대표 흐름입니다. `모델 대기`, `부분 이해`, `검토 필요`, `처리 실패`, `만료됨`, `사용 중지`는 질문 전에 조치가 필요한 상태입니다.

### 8.7 Source 선택

목록에서 Source를 선택하면 현재 질문 Context가 바뀝니다. 다른 Source를 선택하면 이전 답변을 새 Source의 근거로 오해하지 않도록 답변 표시가 초기화될 수 있습니다.

### 8.8 Source 삭제

삭제는 Source 원본, Version, Citation과 산출물 계보에 영향을 줄 수 있습니다. 화면의 삭제 상태를 확인하고, 삭제 요청 뒤 같은 Source를 중복 등록하지 않습니다. Connector 삭제는 외부 시스템의 원본 데이터를 삭제하지 않습니다.

## 9. Daon 승인 지식

승인 지식 목록에는 생산자와 Version, 권위와 등록 상태가 표시될 수 있습니다. 질문 Context에 승인 지식을 선택하면 Citation의 origin이 Daon 지식으로 구분됩니다.

현재 중요한 제한이 있습니다. 권위 순서, 사용자 가중치, 충돌 처리와 강제 RuleSet을 위한 UI·데이터·별도 모듈이 존재하지만 실제 질문 서비스 경로 전체에 자동 적용된다고 보장할 수 없습니다. 중요한 의사결정은 표시된 권위만 믿지 말고 Citation 원문과 조직 검토 절차로 확인합니다.

## 10. 질문과 답변

### 10.1 근거 질문하기

1. `사용 가능` 상태의 Source 또는 승인 지식을 선택합니다.
2. 가운데 입력란에 질문을 작성합니다.
3. 선택 상태가 `작업 상담 · Source 사용` 등으로 표시되는지 확인합니다.
4. 질문을 전송합니다.
5. 답변과 Citation을 함께 확인합니다.

### 10.2 작업 상담

Source를 선택하지 않은 경우 화면에는 `작업 상담 · 근거 미사용`이 표시됩니다. 현재 허용된 일반 대화는 인사, 감사, 도움말과 Daon 사용법처럼 좁은 범위입니다. 문서 사실이나 업무 판단에는 사용하지 않습니다.

### 10.3 질문 작성 요령

- 무엇을 찾을지 명시합니다.
- 원하는 결과 형식을 적습니다.
- 기간, 대상, 예외 조건을 포함합니다.
- 한 질문에 너무 많은 업무를 섞지 않습니다.
- 답변에 근거가 부족하면 범위를 좁혀 다시 질문합니다.

### 10.4 질문 실행 중 오류

- 선택 모델이 없으면 `LLM 설정`을 확인합니다.
- Provider가 준비되지 않았으면 `운영상태`를 확인합니다.
- 외부 전송이 차단되면 조직 정책을 확인합니다.
- Source가 준비되지 않았으면 처리 완료를 기다립니다.
- 같은 요청을 빠르게 반복해 중복 Run을 만들지 않습니다.

## 11. Citation 검토

Citation은 답변이 참조한 근거 위치입니다.

1. 답변마다 Citation이 있는지 확인합니다.
2. PDF이면 표시된 페이지를 엽니다.
3. Daon 지식이면 지식 origin과 위치를 확인합니다.
4. 원문 문장과 답변 해석을 비교합니다.
5. 질문에 선택하지 않은 Source가 섞이지 않았는지 확인합니다.
6. Citation이 없거나 불충분하면 결과를 승인하지 않습니다.

현재 Citation 화면은 페이지 또는 지식 위치 중심입니다. Source 이름, Version과 처리 상태는 Source 패널과 함께 대조합니다.

## 12. 업무 Studio

### 12.1 산출물 유형과 형식

- 근거 기반 보고서: DOCX, PDF
- 제약·준수 점검표: XLSX, CSV, PDF
- 비교·데이터 표: XLSX, CSV, PDF
- 지식 구조도: JSON, SVG, PNG, PDF
- 업무 문서 초안: DOCX, PDF
- 슬라이드: PDF, JSON
- 인포그래픽: SVG, PNG, PDF, JSON
- 플래시카드: JSON, CSV, PDF
- 퀴즈: JSON, CSV, PDF
- AI 오디오: JSON 계약만 존재하며 전용 Provider가 없으면 사용 불가
- 동영상: JSON 계약만 존재하며 전용 Provider가 없으면 사용 불가

산출물별 형식은 현재 서버와 조직 정책에 따라 더 제한될 수 있습니다.

### 12.2 생성 설정

필수 설정은 목적, 독자, 언어, Source Version, 분량, 구성, 출력 형식과 검토 조건입니다. 조직 정책으로 잠긴 값은 Workspace 화면에서 변경할 수 없습니다.

1. 산출물 유형을 선택합니다.
2. 필수 설정을 입력합니다.
3. `설정 확인`을 선택합니다.
4. 현재 모델과 정책 요약을 확인합니다.
5. `생성`을 선택합니다.

### 12.3 Library와 상태

생성 결과는 `Library`에 저장됩니다. 대표 상태는 `초안`, `생성 중`, `검토 중`, `수정 필요`, `승인됨`, `전달됨`, `생성 실패`, `사용 불가`입니다.

### 12.4 Version 만들기

기존 Version을 직접 덮어쓰지 않습니다. 변경 이유와 내용을 입력한 뒤 다음 중 하나를 선택합니다.

- `편집 새 Version`: 사용자가 직접 수정한 Version
- `AI 재생성 새 Version`: AI로 다시 생성한 Version
- `설정 변경 새 Version`: 생성 설정 변경을 반영한 Version

### 12.5 검토와 승인

1. 작성자가 `검토 요청`을 선택합니다.
2. 검토자가 내용과 Citation을 확인합니다.
3. 필요한 경우 수정 의견을 남깁니다.
4. 작성자 또는 검토자가 `승인 요청`을 선택합니다.
5. 승인자가 `승인` 또는 `수정 요청`을 선택합니다.

권한이 없거나 승인 요청이 만들어지지 않은 상태에서는 버튼이 비활성화됩니다.

### 12.6 내보내기·전달·생산 지식 등록

승인된 산출물만 `내보내기`와 `전달`을 사용할 수 있습니다. 생산 지식 등록은 자동이 아니며 사용자가 명시적으로 선택해야 합니다. 전달 대상과 조직 정책을 확인한 뒤 실행합니다.

## 13. LLM 설정

`설정 → LLM 설정`은 시스템 Provider 연결과 현재 Workspace의 기본 모델을 관리하는 화면입니다. 시스템 관리자 여부에 따라 보이는 범위가 다릅니다.

- 시스템 관리자: 모든 Workspace가 함께 사용하는 이름 있는 Provider 연결을 추가·수정하고, 키를 교체·삭제하며, 모델 카탈로그와 모델 기능을 관리합니다.
- Workspace 권한 사용자: 현재 Workspace의 `텍스트 생성`, `이미지 이해`, `문서 분석` 기본 모델을 선택합니다.
- 준비 중 기능: 임베딩, 재정렬, 오디오·음성·동영상·이미지 생성 등 실행 Adapter가 연결되지 않은 기능은 `준비 중`으로 표시되며 기본값으로 선택할 수 없습니다.

### 13.1 시스템 Provider 연결 추가

시스템 관리자로 로그인한 뒤 다음 순서로 진행합니다.

1. `설정 → LLM 설정`을 엽니다.
2. `시스템 Provider 연결`에서 `연결 추가`를 선택합니다.
3. `Connection ID`에 영문·숫자와 `-`, `_`, `.`, `:`만 사용한 고유 ID를 입력합니다. 저장 후에는 바꿀 수 없습니다.
4. `Provider`를 선택하고 사람이 구분하기 쉬운 `연결 이름`을 입력합니다.
5. 서버에서 접근 가능한 HTTPS 또는 승인된 내부 HTTP `Endpoint`를 입력합니다.
6. OmniRoute나 Eoul Gateway처럼 모델 목록을 자동 제공하지 않는 Gateway이면 `Logical model IDs`에 실제 Gateway에 등록한 모델 ID를 한 줄에 하나씩 입력합니다.
7. 외부 Provider나 Gateway이면 `API Key 또는 Client Key`를 입력합니다. 인증이 필요 없는 Ollama는 비워 둡니다.
8. `현재 관리자 비밀번호`를 입력합니다.
9. `연결 활성`을 확인합니다. 키가 있는 Provider는 `키 저장 및 연결 확인`, 무키 Ollama는 `연결 저장`을 선택합니다.
10. 연결 카드가 `확인됨`이고 모델 목록이 나타나는지 확인합니다. 무키 Ollama는 `Credential 없음`으로 표시될 수 있으며 이것만으로 오류는 아닙니다.

키와 저장된 Endpoint 원문은 화면에 다시 표시되지 않습니다. 화면·로그·문의 글에 키를 붙여 넣지 않습니다. 연결 확인 성공은 해당 Endpoint와 모델 카탈로그를 확인했다는 뜻이며, 실제 질문·Source·Studio 흐름까지 성공했다는 뜻은 아닙니다.

현재 질문·일반 대화 실행 경로에 연결된 Provider는 Ollama, Groq, Mistral, Upstage, OpenRouter, OmniRoute와 Eoul Gateway입니다. Cerebras, OpenAI, Gemini와 Anthropic은 코드 값이 남아 있더라도 현재 실행 Adapter가 없으므로 실제 질문용으로 선택하지 않습니다.

### 13.2 Ollama Endpoint 여러 개 등록

Ollama는 Endpoint마다 별도 이름과 Connection ID를 부여해 동시에 등록합니다. 예를 들어 사내 LAN 주소, HTTPS Gateway 주소와 다른 Ollama 서버를 각각 별도 연결로 만들 수 있습니다.

1. 첫 번째 Ollama 주소를 `ollama-lan` 같은 ID와 `사내 Ollama` 같은 이름으로 등록합니다.
2. 두 번째 주소를 `ollama-https` 같은 다른 ID와 이름으로 등록합니다.
3. 각 연결의 카탈로그에서 실제 모델이 따로 조회되는지 확인합니다.
4. Workspace 기본 모델에서 필요한 연결과 모델 조합을 선택합니다.

주소는 예시에 고정되지 않습니다. Daon User의 API 컨테이너가 실제로 접근할 수 있는 주소를 사용해야 하며, 브라우저용 `localhost`나 Docker 내부 이름을 사용자 화면에서 임의로 입력해 우회하지 않습니다.

### 13.3 OpenRouter·OmniRoute·Eoul Gateway

- OpenRouter: OpenAI 호환 Endpoint와 API Key를 등록합니다. 모델 목록은 Provider가 제공하는 카탈로그를 사용합니다.
- OmniRoute: 라우팅 Gateway Endpoint, Client Key와 Gateway에 등록된 Logical model ID를 입력합니다.
- Eoul Gateway: Daon User 서버에 함께 설치한 형태와 별도 서버에 배포한 형태 모두 사용할 수 있습니다. Daon User에서는 접근 가능한 Gateway Endpoint, Client Key와 Logical model ID만 등록합니다.

OmniRoute와 Eoul Gateway의 하위 Provider 선택·우선순위·Fallback은 Gateway가 책임집니다. Daon User는 사용자가 선택한 하나의 논리 모델을 한 번 호출하며 Gateway 내부 라우팅을 중복 구현하지 않습니다.

### 13.4 Workspace 기본 모델 선택

1. `Workspace 기본 모델`에서 `텍스트 생성`, `이미지 이해` 또는 `문서 분석` 카드를 찾습니다.
2. `연결 이름 · 모델 ID` 형식의 항목을 선택합니다.
3. `기본 모델 저장`을 선택합니다.
4. 저장 완료 문구를 확인한 뒤 새 질문 또는 새 처리 Run으로 실제 호출을 검증합니다.

선택 목록에는 활성화되고, 연결 확인과 카탈로그 조회가 끝났으며, 해당 기능이 확인된 모델만 표시됩니다. 수동 역할 매핑 화면은 없습니다. Provider가 보고한 기능을 시스템 관리자가 `모델 기능 보정`에서 확인할 수 있지만, `준비 중` 기능은 보정으로 실행 가능하게 만들 수 없습니다.

### 13.5 키 교체·삭제·카탈로그 새로고침

- 키 교체: 기존 연결을 선택하고 새 키와 현재 관리자 비밀번호만 입력한 뒤 `키 저장 및 연결 확인`을 선택합니다. 저장된 Endpoint를 다시 입력하거나 worker를 재생성할 필요가 없습니다. 다음 요청부터 DB의 최신 자격증명 버전을 읽습니다.
- 키 삭제: 현재 관리자 비밀번호를 입력하고 `키 삭제`를 선택합니다. 연결과 모델 카탈로그 기록은 남지만 Provider 실행은 차단됩니다.
- 카탈로그 새로고침: Provider에서 모델을 추가·삭제한 뒤 현재 관리자 비밀번호를 입력하고 `카탈로그 새로고침`을 선택합니다. 사라진 모델은 선택 목록에서 제거되며 기존 Workspace 기본값에 영향이 있는지 확인해야 합니다.

### 13.6 기존 환경변수 키 1회 이관(운영자)

이 절차는 이전 배포에서 Provider 키를 환경변수로 사용하던 경우에만 한 번 수행합니다. 일반 사용자는 실행하지 않습니다.

1. 배포 전에 `DAON_PROVIDER_CREDENTIAL_KEY_FILE`이 32바이트 이상의 비공개 master key 파일을 가리키는지 확인합니다.
2. DB migration 0040 이상이 적용되어 기존 Provider 설정이 시스템 연결로 이관되었는지 확인합니다.
3. 기존 키가 서버 환경에 있는 동안 API 이미지의 `/app/scripts/import-provider-credentials.py`를 한 번 실행합니다. 명령에는 키 값을 직접 적지 말고 기존 환경변수 이름만 전달합니다.
4. `PROVIDER_CREDENTIAL_IMPORT_COMPLETED imported=... skipped=... unused_provider_types=...` 결과만 기록합니다. 키 원문은 출력되지 않습니다.
5. 같은 명령을 다시 실행했을 때 이미 Credential이 있는 연결은 변경하지 않습니다.
6. 화면에서 연결별 `확인 필요` 상태를 선택해 `키 저장 및 연결 확인` 또는 카탈로그 새로고침으로 실제 Provider를 검증합니다.
7. 검증 후 배포 환경의 기존 `*_API_KEY`와 `OLLAMA_BASE_URL` 항목을 제거하고 API·document-worker에 master key 파일만 read-only Secret으로 제공합니다.

이관 도구는 migration 0040이 만든 기존 연결에만 키를 넣습니다. 환경변수만 있고 대응 연결이 없으면 새 Endpoint를 추측해 만들지 않으며 `unused_provider_types`로 집계합니다.

## 14. 출력·버전 설정

산출물 유형별 기본 출력 형식을 선택합니다. 변경한 뒤 `저장`을 선택합니다. 저장하지 않은 변경이 있는 상태에서 닫으면 `저장`, `버리기`, `계속 편집` 중 하나를 선택해야 합니다.

Version 저장 방식은 append-only입니다. 화면 설정을 바꾸더라도 기존 산출물 Version은 삭제되지 않습니다.

## 15. 동기화·승인

1. `설정 → 동기화·승인`을 엽니다.
2. `동기화 Preview`에서 대기 항목과 Version을 확인합니다.
3. 승인할 항목만 체크합니다.
4. 현재 비밀번호로 Step-up을 수행합니다.
5. `선택 항목 승인`을 실행합니다.

Daon은 Preview 전체를 자동 승인하거나 자동 전송하지 않습니다. 충돌 상태이면 자동 덮어쓰지 말고 Version을 비교합니다.

## 16. 조직 정책

Workspace에서는 조직의 외부 전송 정책을 읽기 전용으로 확인합니다.

- 정책 모드: 외부 전송 차단 또는 승인된 외부 전송
- 허용 Provider 종류
- 허용 목적지
- 데이터 분류
- 최대 전송량
- 마스킹 필요 여부
- 삭제 처리 필요 여부
- 필수 승인자
- Workspace 적용 결과

조직 차단 정책은 Workspace에서 완화할 수 없습니다. 사용자가 Endpoint를 변경하거나 다른 Provider로 우회해서는 안 됩니다.

## 17. 라이선스

### 17.1 일반 사용자

제품, Edition, 일부만 표시된 License ID, 상태, 발급·만료일, 허용 기능과 사용 한도를 읽기 전용으로 확인합니다.

상태는 `미적용`, `정상`, `30일 이내 만료`, `만료`, `한도 도달`로 표시될 수 있습니다.

### 17.2 적용 권한이 있는 관리자

1. 승인된 JSON License document를 준비합니다.
2. 현재 비밀번호를 입력합니다.
3. `Step-up 후 검증·적용`을 선택합니다.
4. 제품, 조직, 기간, Schema와 서명 검증 결과를 확인합니다.

License 원문과 비밀번호를 로그나 문의 글에 첨부하지 않습니다. 일반 사용자에게는 적용 입력란이 보이지 않아야 합니다.

## 18. 운영상태

Workspace App Bar의 `운영상태`에서 다음 구성요소를 확인합니다.

- Provider: LLM Provider와 선택 모델
- API: Workspace API
- Storage: Database와 Object Storage
- Sync: 승인 또는 전송 대기
- Queue: 처리 작업 대기와 실패

각 카드가 제공하는 `LLM 설정 열기`, `동기화 설정 열기`, `상태 새로고침` 같은 안전한 복구 동작만 사용합니다. 내부 Host, Port 또는 Stack 정보를 직접 입력해 우회하지 않습니다.

## 19. 화면 설정과 접근성

Notebook 홈의 `설정 → 화면 설정`에서 `시스템 설정`, `밝게`, `어둡게`를 선택합니다. `화면 설정 초기화`는 화면 Preference만 초기화하며 Notebook, Source, 질문과 산출물을 삭제하지 않습니다.

Dialog는 최초 입력 위치로 Focus를 이동하고, Tab 순환과 Escape 닫기를 지원합니다. 닫은 뒤에는 호출한 버튼으로 Focus가 돌아와야 합니다. Mobile 화면은 운영체제 글자 크기 조정을 지원하도록 설계되어 있습니다.

## 20. Windows Desktop 사용 경계

- Windows 앱은 로컬 Source와 오프라인 Studio 초안을 사용할 수 있습니다.
- Cloud와 끊어진 상태에서는 외부 Provider 호출과 Cloud 전용 작업이 제한됩니다.
- 재연결 후 자동 전체 동기화하지 않고 Preview와 승인 절차를 거칩니다.
- 로컬 작업과 Cloud Version이 충돌하면 어느 한쪽을 자동 덮어쓰지 않습니다.
- Desktop에서 지원하는 Studio 범위는 현재 연결된 Local Service와 모델에 따라 달라집니다.

설치, 업데이트, 제거와 복구 절차는 제공된 설치 패키지의 운영 안내를 따릅니다. 현재 설치 패키지를 받지 못했다면 임의 개발 빌드를 사용하지 않습니다.

## 21. Mobile 사용 경계

Mobile 계약상 허용되는 작업에는 제목·텍스트 블록·간단한 표 셀 편집, 검토 의견, 수정 요청, 승인·거부, 알림 처리와 Citation 열기가 포함됩니다.

섹션 구조 변경, Layout 변경, 표 구조 변경, 근거 연결 변경, 생성 설정 변경과 전체 재생성은 Mobile에서 허용되지 않으며 Web·Windows에서 계속해야 합니다.

현재 Mobile 실제 배포와 실기기 검증은 미완료 범위입니다. 조직이 승인한 설치본과 서버 연결이 없다면 Mobile Shell의 화면 계약만으로 실제 사용 가능하다고 판단하지 않습니다.

## 22. 사용자 설명서 Hub

1. `설정 → 사용자 설명서`를 엽니다.
2. 검색란에 문서 제목이나 설명을 입력합니다.
3. 문서를 선택해 Web에서 읽습니다.
4. 필요한 경우 `DOCX` 또는 `PDF`를 선택해 내려받습니다.
5. Hub 상단의 Release와 언어를 확인합니다.

다운로드는 허용된 same-origin 문서만 사용합니다. 내부 경로나 임의 URL을 조합하지 않습니다.

## 23. 예상 결과와 보안 사용 원칙

- 비밀번호, 이메일 인증 토큰, 재설정 토큰, API Key와 License 원문을 공유하지 않습니다.
- Source 원문이나 LLM 응답을 오류 로그에 그대로 붙이지 않습니다.
- 권한 오류를 다른 계정, 내부 주소 또는 임시 Token으로 우회하지 않습니다.
- 승인과 외부 전송은 화면에서 명시적으로 선택합니다.
- 공용 PC에서는 로그아웃 후 브라우저를 닫습니다.
- 권한이 축소되면 이전에 열었던 화면도 계속 접근할 수 있다고 가정하지 않습니다.

## 24. 제한·오류 대응

### 보호된 화면이 로그인 없이 보임

정상 상태가 아닙니다. 브라우저를 닫고 운영 담당자에게 접속 주소, 발생 시각과 화면 종류만 전달합니다. 화면에 포함된 업무 데이터는 공개 채널에 첨부하지 않습니다.

### 로그아웃 후 Notebook이 다시 보임

페이지를 새로고침하고 `/notebooks` 직접 접근을 확인합니다. 계속 보이면 Session 종료 결함일 수 있으므로 추가 작업을 중지하고 신고합니다.

### Source 목록을 불러오지 못함

`운영상태`에서 API와 Storage를 확인하고 다시 불러옵니다. 기존 Source를 삭제하거나 같은 파일을 반복 등록하지 않습니다.

### Source가 `부분 이해` 또는 `검토 필요`

해당 Source만으로 최종 결과를 승인하지 않습니다. PDF로 변환해 재등록하거나 조직이 지원하는 Adapter 준비 여부를 확인합니다.

### 선택 모델이 없음

`LLM 설정`의 `Workspace 기본 모델`에서 해당 기능에 사용할 연결과 모델을 선택했는지 확인합니다. 선택 항목이 없으면 시스템 관리자에게 연결 활성 상태, 연결 확인 결과, 모델 카탈로그와 기능 판별을 확인해 달라고 요청합니다.

### Provider 연결 확인이 실패함

Endpoint에 오타가 없는지, Daon User 서버에서 해당 주소로 통신할 수 있는지, 키가 유효한지, Gateway의 Logical model ID가 실제 등록값과 일치하는지 확인합니다. 키 원문이나 Provider 응답 본문을 오류 보고에 포함하지 않습니다. 키 교체만 필요한 경우 Endpoint를 다시 입력하거나 worker를 재생성하지 않습니다.

### 외부 전송이 거부됨

`조직 정책`에서 허용 Provider, 목적지, 데이터 분류, 최대 전송량과 마스킹 조건을 확인합니다. 정책을 우회하지 않습니다.

### Studio 버튼이 비활성화됨

필수 생성 설정, Source Version, 설정 확인 여부, 검토·승인 단계와 현재 권한을 확인합니다.

### 내보내기가 되지 않음

산출물 상태가 `승인됨`인지, 선택한 형식이 해당 유형에 허용되는지, 라이선스와 현재 권한이 유효한지 확인합니다.

### 오류를 담당자에게 전달할 때

다음 정보만 전달합니다.

- 발생 시각
- 사용한 플랫폼과 화면 이름
- 수행하려던 동작
- 화면에 표시된 안전한 오류 코드 또는 문구
- 재현 여부

비밀번호, Token, Source 원문, 내부 주소와 전체 응답 본문은 전달하지 않습니다.

## 25. 현재 구현·검증 제한

- 지식 권위·가중치·충돌·강제 RuleSet은 실제 질문 경로 전체에 배선된 것으로 검증되지 않았습니다.
- 실제 질문 실행은 선택된 단일 모델을 사용하며 다중 후보 자동 정렬과 자동 Fallback을 제공한다고 설명할 수 없습니다.
- Source 선택기는 12개 파일 형식을 허용하지만 현재 운영 의미 이해가 모두 완성된 것은 아닙니다.
- Mobile 앱의 설치·인증·공개 API·실기기 전체 흐름은 미검증입니다.
- Evidence Hub의 일부 화면은 prototype fixture이며 실제 서버 저장 성공을 증명하지 않습니다.
- 브라우저·기기별 전체 사용자 시나리오는 별도 실제 QA가 필요합니다.

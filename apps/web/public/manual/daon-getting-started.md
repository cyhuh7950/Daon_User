# Daon Getting Started

- Release: 1.0.0
- 문서 업데이트: 2026-10-22
- 언어: 한국어(ko-KR)
- 대상: Daon을 처음 사용하는 일반 사용자
- 목표: 로그인부터 첫 Notebook 작업과 안전한 로그아웃까지 직접 따라 합니다.

> 이 문서는 현재 제품에서 확인할 수 있는 기능만 사용 절차로 설명합니다. 화면에 항목이 보이더라도 서버 연결이나 Provider가 준비되지 않으면 사용할 수 없는 기능은 별도로 표시합니다.

## 1. 목적과 Daon에서 할 수 있는 일

Daon은 한 Notebook 안에서 자료를 등록하고, 자료에 대해 질문하고, 답변 근거를 확인하고, 업무 산출물을 만드는 프로그램입니다.

기본 흐름은 다음과 같습니다.

1. 계정으로 로그인합니다.
2. Notebook을 새로 만들거나 기존 Notebook을 엽니다.
3. Notebook에 Source를 등록합니다.
4. Source가 `사용 가능` 상태가 될 때까지 기다립니다.
5. Source를 선택하고 질문합니다.
6. 답변과 Citation을 함께 확인합니다.
7. 필요한 경우 업무 Studio에서 산출물을 만듭니다.
8. 작업을 마치면 로그아웃합니다.

## 2. 접근 경로와 시작하기 전에 준비할 것

공개 범위에서는 로그인·가입 화면과 공개로 배포된 설명서를 볼 수 있습니다. Notebook, Source, 질문, Citation과 Studio는 로그인 후 현재 Session과 Workspace 권한을 검사합니다.

- 운영 담당자가 안내한 Daon 접속 주소
- 가입이 완료된 사용자 ID와 12자 이상의 비밀번호
- 첫 실습에 사용할 PDF 파일 1개
- 외부 LLM을 사용한다면 운영 담당자가 Workspace에 준비한 Provider와 모델

비밀번호, 인증 토큰, API Key는 다른 사람에게 전달하거나 오류 화면에 붙여 넣지 마세요. Daon 담당자에게 문의할 때는 화면에 표시된 안전한 오류 문구나 오류 코드만 전달합니다.

## 3. 조작: 계정 만들기와 로그인

이미 사용할 계정이 있다면 `3.3 로그인`부터 진행합니다.

### 3.1 가입하기

1. Daon 첫 화면에서 `가입하기`를 선택합니다.
2. `사용자 ID`를 입력합니다.
3. 실제로 확인할 수 있는 `메일 주소`를 입력합니다.
4. 12자 이상의 비밀번호를 입력합니다.
5. `가입`을 선택합니다.
6. 화면에 인증 메일 요청 안내가 표시되는지 확인합니다.

가입만으로 로그인이 완료되지는 않습니다. 이메일 인증이 끝나야 로그인할 수 있습니다.

### 3.2 이메일 인증하기

1. 가입에 사용한 메일함을 엽니다.
2. 받은 인증 토큰을 Daon의 `이메일 인증 토큰` 입력란에 붙여 넣습니다.
3. `이메일 인증`을 선택합니다.
4. `이메일 인증이 완료되었습니다.` 안내를 확인합니다.
5. 메일을 받지 못했다면 사용자 ID 또는 메일 주소를 확인하고 `인증 재전송`을 선택합니다.

인증 토큰은 비밀번호처럼 취급합니다. 인증이 끝난 토큰을 메신저나 문의 글에 남기지 마세요.

### 3.3 로그인하기

1. 로그인 화면에서 `사용자 ID`를 입력합니다.
2. `비밀번호`를 입력합니다.
3. `로그인`을 선택합니다.
4. 로그인이 성공하면 Notebook 홈으로 이동합니다.

로그인하지 않은 상태에서 `/notebooks` 같은 보호된 주소를 직접 열면 Notebook 내용이 보여서는 안 됩니다. 로그인 화면으로 이동하거나 인증이 필요하다는 안내가 표시되어야 합니다.

보호된 초기 시스템 관리자 계정은 일반 계정과 다릅니다. 로그인 ID는 `admin`이고 이메일은 없습니다. 이 계정은 삭제하거나 중지할 수 없습니다. 최초 시작 또는 운영자가 서버 콘솔에서 초기화한 직후에만 `admin/admin`으로 로그인합니다. 이 값은 상시 비밀번호가 아닙니다.

초기 관리자라면 다음 순서로 계속합니다.

1. 로그인 화면의 `사용자 ID`에 `admin`, `비밀번호`에 초기 비밀번호를 입력하고 `로그인`을 선택합니다.
2. 자동으로 `/password-change`의 `새 비밀번호 설정` 화면으로 이동하는지 확인합니다.
3. `현재 비밀번호`, 12자 이상의 `새 비밀번호`, `새 비밀번호 확인`을 입력합니다.
4. `비밀번호 변경`을 선택합니다.
5. 로그인 화면으로 돌아오면 새 비밀번호로 다시 로그인합니다.

비밀번호를 바꾸기 전에는 Notebook 데이터가 보이지 않습니다. 다른 제품 요청은 HTTP 403과 `PASSWORD_CHANGE_REQUIRED`로 거부됩니다. 비밀번호 변경 성공 직후 모든 기존 Session과 refresh family가 폐기되고 `admin/admin`은 즉시 무효가 됩니다.

### 3.4 비밀번호를 잊었을 때

1. 로그인 화면에서 `비밀번호를 잊으셨나요?`를 선택합니다.
2. 사용자 ID 또는 메일 주소를 입력합니다.
3. `재설정 메일 요청`을 선택합니다.
4. 메일로 받은 재설정 토큰과 새 비밀번호를 입력합니다.
5. `비밀번호 재설정`을 선택합니다.
6. 로그인 화면으로 돌아가 새 비밀번호로 로그인합니다.

## 4. Workspace와 Notebook 이해하기

작업 자료의 접근 경계는 Workspace입니다. 조직 가입은 별도 신청·승인 절차이며, 승인된 조직과 Workspace의 현재 권한에 따라 사용할 수 있는 기능이 달라집니다.

- Workspace: 접근 권한과 작업 범위를 묶는 공동 작업 경계입니다.
- Notebook: Workspace 안에서 만드는 개별 작업 단위입니다.
- Source: Notebook에서 질문과 생성의 근거로 선택하는 자료입니다.
- Studio: 선택한 Source와 설정을 사용해 Notebook 안에 산출물과 새 Version을 만듭니다.

로그인 Session에는 사용할 Workspace가 지정됩니다. Notebook을 열거나 Source·Studio를 사용할 때 서버가 그 Workspace의 현재 권한을 다시 확인합니다. 조직 관리 권한이 있는 사용자는 별도 조직 관리자 화면에서 초대와 가입 승인을 처리합니다. 일반 사용자는 본인의 가입 신청만 확인하며 Workspace 관리자 역할만으로 시스템 관리 권한을 얻지 않습니다.

Workspace 내부의 멤버 권한 모델과 시스템 관리자 계정 관리는 서로 다른 범위입니다. Workspace 관리자 역할만으로는 `사용자 관리` 메뉴나 `/admin`을 사용할 수 없습니다. 조직 관리자는 별도 조직 관리자 화면에서 연결된 Workspace의 초대와 실제 역할을 관리하고, 정책은 별도 관리 권한과 추가 인증으로 변경합니다. 전체 계정 검색과 일반 사용자 중지·재활성화는 아래의 시스템 관리자 전용 기능입니다.

### 4.1 시스템 관리자의 사용자 관리

로그인된 시스템 관리자에게만 Notebook 홈의 `설정` 메뉴에 `사용자 관리`가 표시됩니다.

1. `설정`을 열고 `사용자 관리`를 선택합니다.
2. `/admin` 화면의 `사용자 목록`이 표시되는지 확인합니다.
3. 각 사용자 행에서 등록 이메일 주소 전체를 확인합니다. 이메일 미등록 계정은 `이메일 없음`으로 표시됩니다.
4. `사용자 검색`에 로그인 ID, 사용자 ID 또는 이메일을 입력해 대상을 찾습니다.
5. `상태 필터`에서 `전체`, `활성`, `중지` 중 하나를 선택합니다.
6. 일반 사용자의 `중지` 또는 `재활성화`를 선택합니다.
7. 상태 문구가 `활성 계정` 또는 `중지된 계정`으로 바뀌었는지 확인합니다.

등록 이메일 주소 전체는 로그인된 시스템 관리자의 `/admin` 사용자 목록에서만 표시됩니다. 일반 사용자와 다른 화면에는 이 정보를 표시하지 않습니다. `이메일 인증 대기` 계정은 목록과 검색에서 확인할 수 있지만 상태 변경은 할 수 없습니다. 초기 admin 행에는 `이메일 없음`, `보호된 시스템 관리자`, `보호됨`이 표시되며 상태 버튼을 사용할 수 없습니다. 보호된 admin의 중지 요청은 HTTP 409 `PROTECTED_ADMIN_ACCOUNT`로 거부됩니다. 계정 삭제 기능은 제공하지 않습니다. 일반 사용자는 `사용자 관리` 메뉴를 볼 수 없고 `/admin` 직접 접근과 관리자 API가 HTTP 403 `FORBIDDEN`으로 거부됩니다.

### 4.2 admin 비밀번호를 잊었을 때

일반 사용자는 `비밀번호를 잊으셨나요?` 절차를 사용하지만 이메일이 없는 초기 admin은 운영자가 서버 콘솔에서만 복구합니다.

1. 운영자는 승인된 배포 절차로 현재 API 컨테이너의 서버 콘솔에 접속합니다.
2. API가 사용하는 것과 같은 Runtime 환경과 데이터베이스 접근 권한이 준비되었는지 확인합니다. 실제 서버 경로, DSN, Secret 값은 명령행·문의 글·보고서에 적지 않습니다.
3. API 컨테이너에서 프로젝트 명령 `python -m daon_user_api.admin_cli reset-initial-password`를 정확히 한 번 실행합니다.
4. 성공하면 `INITIAL_ADMIN_PASSWORD_RESET`이 표시되고 종료 코드는 0입니다. Runtime 실패는 `INITIAL_ADMIN_PASSWORD_RESET_FAILED:<오류 코드>`를 표시하고 종료 코드 1로 끝납니다. 잘못된 인자나 지원하지 않는 옵션은 명령 사용법인 `usage:`를 표시하고 종료 코드 2로 끝납니다. 어느 경우에도 비밀번호·hash·token을 출력하지 않으며, Runtime 실패 원인을 확인하기 전에 반복 실행하지 않습니다.
5. 성공 시 admin의 기존 Session과 refresh family가 모두 폐기됩니다. 브라우저에서 다시 `admin/admin`으로 로그인한 뒤 `/password-change`에서 즉시 새 비밀번호를 설정합니다.

이 명령은 고정된 보호 admin만 대상으로 하며 사용자 ID나 비밀번호 인자를 받지 않습니다. Web 화면이나 API로 초기화를 시도하지 마세요.

### 4.3 조직 가입과 승인 확인

1. 로그인한 뒤 `조직 가입`(`/organization/join`)을 엽니다.
2. 조직 관리자가 안전한 별도 경로로 전달한 유효한 `초대코드`를 입력합니다.
3. `가입 신청`을 누르고 `본인 가입 신청`에서 승인 대기·승인됨·거부됨을 확인합니다.
4. `상태 새로고침`으로 다시 확인합니다. 가입 신청만으로 접근 권한이 생기지 않습니다.

결과 미확정 안내가 나오면 `동일 신청 결과 확인`을 사용합니다. 코드를 반복 제출하거나 다른 조직 주소로 우회하지 않습니다. 조직 관리자는 가입 신청과 대상 Workspace를 확인한 뒤 승인합니다. 초대코드는 메일로 자동 발송되지 않습니다.

## 5. Notebook 홈 익히기

Notebook 홈은 작업 단위를 찾고 여는 화면입니다.

- `새 Notebook`: 새 작업 공간을 만듭니다.
- `Notebook 제목 검색`: 제목으로 Notebook을 찾습니다.
- `최근 수정` 또는 `제목`: Notebook 목록의 정렬 기준을 바꿉니다.
- Grid/List 버튼: 카드 보기와 목록 보기를 전환합니다.
- Notebook 카드: 선택한 Notebook을 엽니다.
- 카드의 `⋮` 메뉴: Notebook 영구 삭제 절차를 엽니다.
- `설정`: 화면 설정, 라이선스, 사용자 설명서와 로그아웃 메뉴를 엽니다. 시스템 관리자에게만 `사용자 관리`가 추가됩니다.

## 6. 첫 Notebook 생성하기

1. `새 Notebook`을 선택합니다.
2. `제목`에 작업을 알아볼 수 있는 이름을 입력합니다. 제목은 필수입니다.
3. 필요한 경우 `설명`에 목적이나 담당 업무를 입력합니다.
4. 생성 버튼을 선택합니다.
5. 빈 Workspace가 열리는지 확인합니다.

Notebook은 자동으로 임의의 Source나 모델을 선택하지 않습니다. 사용자가 이 Notebook에서 사용할 Source를 직접 등록하고 선택해야 합니다.

## 7. Workspace 화면 이해하기

Notebook을 열면 다음 세 영역이 나타납니다.

- 왼쪽 `Source·지식·권위`: 파일, 복사한 텍스트, 승인 지식과 연결형 Source를 관리합니다.
- 가운데 `대화·실행`: 질문을 입력하고 답변과 Citation을 확인합니다.
- 오른쪽 `업무 Studio`: 보고서, 표, 문서 초안 등의 산출물을 만들고 저장된 Version을 관리합니다.

화면 위쪽에는 현재 Source 상태와 Cloud 상태가 요약되어 표시될 수 있습니다. `확인 필요`, `주의` 또는 `미확인`이 보이면 질문이나 생성을 반복하기 전에 `운영상태`를 확인합니다.

## 8. 첫 Source 등록하기

첫 실습은 PDF로 진행하는 것을 권장합니다. 현재 운영 질의 경로에서 의미 이해와 페이지 Citation까지 확인된 형식이 PDF이기 때문입니다.

### 8.1 PDF 업로드

1. 왼쪽에서 `Source 추가`를 선택합니다.
2. `파일 업로드` 탭을 선택합니다.
3. 준비한 PDF 파일을 선택합니다.
4. `Source 등록·처리 중입니다.` 안내가 표시되는지 확인합니다.
5. 창을 닫은 뒤 Raw Source 목록에서 파일을 찾습니다.
6. 상태가 `사용 가능`이 될 때까지 기다립니다.

화면의 파일 선택기는 PDF 외에도 DOCX, PPTX, XLSX, CSV, TXT, Markdown, PNG/JPG, 제한형 WAV를 선택할 수 있습니다. 그러나 현재 운영 의미 이해 경로에서 PDF 외 형식 전체가 완성되었다고 보장하지 않습니다. 다른 형식은 등록 후 `부분 이해`, `검토 필요`, `모델 대기`, `처리 실패`가 될 수 있습니다.

### 8.2 복사한 텍스트 등록

1. `Source 추가`에서 `복사한 텍스트`를 선택합니다.
2. 입력란에 텍스트를 붙여 넣습니다.
3. `텍스트 등록`을 선택합니다.
4. Raw Source 목록과 처리 상태를 확인합니다.

민감정보나 외부 전송이 금지된 내용을 붙여 넣기 전에 조직 정책을 확인합니다.

### 8.3 웹사이트와 Drive

`웹사이트`와 `Drive`는 화면에 진입 항목이 있지만 Connector가 연결되어야 사용할 수 있습니다. `연결 준비 필요`가 표시되면 현재 사용자가 해결할 수 있는 문제가 아닙니다. Workspace 운영 담당자에게 Connector 준비를 요청합니다.

### 8.4 MCP 연결

`MCP 연결`에는 국가법령정보센터 연결 등록 흐름이 제공될 수 있습니다. 연결 등록 후 `연결형 Source` 목록에서 상태를 확인합니다. 연결을 삭제해도 외부 서버의 원본 데이터가 삭제되는 것은 아닙니다.

### 8.5 Source 상태 읽기

- `등록됨`: 업로드 요청이 접수되었습니다.
- `보안 확인 중`: 파일 안전성 검사가 진행 중입니다.
- `처리 중`: 내용을 처리하고 있습니다.
- `색인 중`: 질문 검색을 위한 색인을 만들고 있습니다.
- `사용 가능`: 질문과 Studio에 선택할 수 있습니다.
- `모델 대기`: 필요한 모델이 준비되지 않았습니다.
- `부분 이해`: 일부 내용만 처리되어 검토가 필요합니다.
- `검토 필요`: 사람이 결과를 확인해야 합니다.
- `처리 실패`: 이번 처리가 끝나지 않았습니다.
- `만료됨` 또는 `사용 중지`: 현재 질문에 사용할 수 없습니다.
- `삭제 중` 또는 `삭제됨`: 삭제 절차가 진행되었거나 끝났습니다.

`사용 가능`이 아닌 Source를 근거로 결과가 완성되었다고 판단하지 마세요.

## 9. Source를 선택하고 질문하기

### 9.1 근거 질문

1. 왼쪽 Raw Source 목록에서 `사용 가능` 상태의 Source를 선택합니다.
2. 가운데 안내가 `Source에 대해 무엇이든 물어보세요.`로 바뀌는지 확인합니다.
3. 질문 입력란에 구체적인 질문을 입력합니다.
4. 전송 버튼을 선택합니다.
5. 답변이 표시될 때까지 기다립니다.
6. 답변 아래 Citation을 확인합니다.

좋은 질문은 대상과 원하는 결과가 명확합니다. 예: `이 문서의 계약 종료 조건을 항목별로 정리해 줘.`

### 9.2 근거 없는 작업 상담

Source나 승인 지식을 선택하지 않고 인사, 도움말, Daon 사용법 같은 제한된 질문을 할 수 있습니다. 이때 화면에는 `작업 상담 · 근거 미사용`이 표시됩니다.

근거 없는 작업 상담은 문서 사실 확인에 사용하지 마세요. 문서 내용에 관한 질문은 반드시 Source를 선택한 뒤 실행합니다.

### 9.3 추가 인증

조직 정책이나 외부 전송 조건에 따라 현재 비밀번호를 다시 입력하는 Step-up 인증이 요구될 수 있습니다. Step-up은 민감한 동작을 다시 확인하는 절차이며 비밀번호는 저장되지 않아야 합니다.

## 10. 답변과 Citation 확인하기

1. 답변이 질문과 직접 관련되는지 읽습니다.
2. Citation이 있는지 확인합니다.
3. PDF Citation을 선택해 표시된 페이지로 이동하는지 확인합니다.
4. 원문 페이지와 답변 내용을 비교합니다.
5. 근거가 부족하거나 Citation이 열리지 않으면 답변을 확정 자료로 사용하지 않습니다.

Citation에는 페이지 또는 지식 위치가 표시됩니다. Source 이름과 Version 같은 메타데이터는 왼쪽 Source 목록과 선택 상태에서 함께 확인합니다. Citation 표시만으로 권위 순서나 충돌 해결이 자동 적용되었다고 판단하지 마세요.

## 11. 업무 Studio로 첫 산출물 만들기

### 11.1 사용할 수 있는 산출물 유형

현재 Studio 계약에는 다음 유형이 등록되어 있습니다.

- 근거 기반 보고서
- 제약·준수 점검표
- 비교·데이터 표
- 지식 구조도
- 업무 문서 초안
- 슬라이드
- 인포그래픽
- 플래시카드
- 퀴즈
- AI 오디오
- 동영상

슬라이드, 인포그래픽, 플래시카드, 퀴즈는 구조화된 결과 생성 경로가 있습니다. AI 오디오와 동영상은 전용 Provider가 없으면 `사용 불가`로 안전하게 종료됩니다. 화면에 Tile이 보인다는 사실만으로 생성 가능하다고 판단하지 않습니다.

### 11.2 생성 절차

1. 질문에 사용한 Source가 선택되어 있거나 사용할 Source가 `사용 가능`인지 확인합니다.
2. 오른쪽 `업무 Studio`에서 산출물 유형을 선택합니다.
3. 목적, 독자, 언어, Source Version, 분량, 구성, 출력 형식, 검토 조건을 입력합니다.
4. 조직 정책에 의해 잠긴 설정은 해제하지 않습니다.
5. `설정 확인`을 선택합니다.
6. 입력값 요약과 현재 모델을 확인합니다.
7. `생성`을 선택합니다.
8. 생성 중 상태가 끝날 때까지 기다립니다.
9. `Library`에서 저장된 산출물을 선택합니다.
10. 내용, Citation과 Version 상태를 검토합니다.

### 11.3 수정·검토·승인·내보내기

1. 변경 이유와 수정 내용을 입력합니다.
2. 목적에 따라 `편집 새 Version`, `AI 재생성 새 Version`, `설정 변경 새 Version`을 선택합니다.
3. 검토가 필요하면 `검토 요청`을 선택합니다.
4. 검토가 끝난 뒤 `승인 요청`을 선택합니다.
5. 승인 권한이 있는 사용자가 `승인` 또는 `수정 요청`을 선택합니다.
6. 상태가 `승인됨`일 때 `내보내기` 또는 `전달`을 사용합니다.
7. 필요한 경우 명시적으로 `생산 지식 등록`을 선택합니다.

기존 Version은 덮어쓰지 않고 새 Version이 추가됩니다. 승인 전 산출물은 최종본으로 외부에 전달하지 마세요.

## 12. 설정 메뉴 사용하기

Workspace 오른쪽 위 `설정`에는 다음 항목이 있습니다.

- `LLM 설정`: Provider, Deployment, 모델 역할과 선택 상태를 확인합니다.
- `출력·버전`: 산출물별 기본 내보내기 형식과 append-only 저장 방식을 설정합니다.
- `동기화·승인`: 자동 전송 없이 Preview 항목을 선택하고 승인합니다.
- `조직 정책`: 외부 전송, 목적지, 데이터 분류, 최대 전송량, 마스킹과 승인자 조건을 읽습니다.
- `라이선스`: Edition, 상태, 기간, 허용 기능과 사용 한도를 확인합니다.
- `사용자 설명서`: 설명서를 검색하고 Web으로 읽거나 DOCX/PDF로 내려받습니다.
- `로그아웃`: 현재 브라우저 세션을 종료합니다.

### 12.1 알림과 전달함 확인

`알림`(`/notifications`)에서 현재 권한으로 볼 수 있는 항목과 미읽음 수를 확인하고 `읽음 처리`를 선택합니다. 읽음은 승인이나 실행이 아닙니다. 결과 미확정이면 다시 조회하고 새 읽음 요청을 반복하지 않습니다.

`전달함`(`/inbox`)에서 실행 가능한 요청을 찾고 `원 요청 열기`로 이동합니다. 승인·추가 인증은 원 요청 화면에서 별도로 진행합니다. 전달 기록의 `실제 외부 송신 없음`은 메일이나 외부 시스템에 실제 전송되었다는 뜻이 아닙니다. 목록과 링크는 현재 권한으로 다시 확인되므로 권한이 사라지면 열리지 않을 수 있습니다.

### 12.2 운영 백업과 복구 확인

운영 권한이 있는 사용자는 `/operations`의 `운영 상태·복구`를 엽니다. 미수집·미구현은 정상이나 0건으로 해석하지 않습니다. `백업 자료 선택`에서 대상 자료와 계보를 확인하고 명시 동의 후 백업을 요청합니다. 독립 보존 준비가 안 된 서버에서는 완료로 표시되지 않습니다.

복구는 등록 목적지와 정확한 백업을 확인한 뒤 `등록 목적지 Preview 준비`에서 새 비밀번호 추가 인증을 수행합니다. Preview는 복원 실행이 아닙니다. 포함·제외와 만료를 확인하고 `복구 실행 준비`에서 다시 별도 인증·실행합니다. 실행 전 취소 가능한 상태에서는 `복구 요청 취소`를 사용합니다. 독립 전체 DB 복원은 지원하지 않습니다. 자세한 권한·상태별 절차는 사용자 설명서 18절을 확인합니다.

## 13. 안전하게 로그아웃하기

1. 진행 중인 입력이나 설정 변경을 저장하거나 취소합니다.
2. 오른쪽 위 `설정`을 선택합니다.
3. `로그아웃`을 선택합니다.
4. 로그인 화면으로 이동하는지 확인합니다.
5. 브라우저 뒤로 가기 또는 `/notebooks` 직접 입력으로 Notebook 내용이 다시 보이지 않는지 확인합니다.

공용 PC에서는 로그아웃 후 브라우저 창도 닫습니다. 로그아웃 뒤 보호 화면이 다시 보이면 페이지를 새로고침하고 즉시 운영 담당자에게 알립니다.

## 14. 예상 결과와 첫 작업 완료 확인표

- 로그인 후 Notebook 홈이 열렸습니다.
- 새 Notebook을 만들었습니다.
- PDF Source를 등록했습니다.
- Source 상태가 `사용 가능`이 되었습니다.
- Source를 선택하고 질문했습니다.
- 답변의 Citation을 원문과 비교했습니다.
- Studio 산출물을 만들거나 현재 사용할 수 없는 이유를 확인했습니다.
- 설정 메뉴에서 로그아웃했습니다.
- 로그아웃 후 보호된 Notebook 화면에 다시 접근되지 않았습니다.

## 15. 제한·오류 대응

### 로그인이 되지 않음

- 사용자 ID 철자와 비밀번호를 다시 확인합니다.
- 이메일 인증이 완료되었는지 확인합니다.
- 현재 계정에 사용할 Workspace가 준비되었는지 운영 담당자에게 확인합니다.
- 반복 입력으로 계정 잠금 가능성을 높이지 말고 관리자에게 문의합니다.

### Source가 계속 처리 중임

- Source 상태가 바뀌는지 잠시 기다립니다.
- `운영상태`에서 API, Storage, Queue를 확인합니다.
- 같은 파일을 여러 번 올리지 않습니다.
- PDF 외 형식이면 현재 의미 이해 지원 범위를 확인합니다.

### 질문 버튼을 사용할 수 없음

- Source가 `사용 가능`인지 확인합니다.
- 질문 입력란이 비어 있지 않은지 확인합니다.
- `LLM 설정`에서 선택 모델이 있는지 확인합니다.
- 조직 외부 전송 정책이 선택 Provider를 허용하는지 확인합니다.

### Citation이 없거나 열리지 않음

- 답변을 최종 근거로 사용하지 않습니다.
- 질문할 Source를 다시 선택합니다.
- PDF 처리 상태와 페이지 정보를 확인합니다.
- 계속 실패하면 안전한 오류 코드와 발생 시각을 담당자에게 전달합니다.

### Studio 생성이 실패함

- Source와 생성 설정을 다시 확인합니다.
- 현재 산출물 유형과 출력 형식을 확인합니다.
- AI 오디오·동영상은 전용 Provider가 없으면 사용할 수 없습니다.
- `Library`에서 지연된 작업 상태를 다시 확인합니다.

### 내부 주소나 기술 정보가 화면에 보임

- 해당 내용을 공개 채널에 올리지 않습니다.
- 화면 전체 대신 안전한 오류 문구와 발생 시각만 전달합니다.

## 16. 현재 제한사항과 미검증 범위

- PDF 외 등록 형식은 선택기와 등록 계약이 존재하지만 운영 의미 이해가 모두 완성된 것은 아닙니다.
- Daon 승인 지식의 권위·가중치·충돌 처리와 강제 RuleSet은 UI와 일부 모듈이 존재하지만 현재 실제 질문 서비스 경로 전체에서 자동 강제된다고 보장할 수 없습니다.
- 모델 설정은 여러 Provider를 등록할 수 있지만 실제 질문 경로는 선택된 단일 모델을 사용합니다. 다중 후보 자동 정렬과 장애 시 자동 Fallback은 현재 제공되는 사용자 기능으로 설명하지 않습니다.
- Mobile 앱은 공용 Shell과 화면 계약이 있으나 실제 설치·실기기 전체 기능 검증이 완료되지 않았습니다.
- Evidence Hub는 일반 사용자용 업무 앱이 아닙니다.


## 최신 사용 절차와 오류 대응

### 파일 입력과 제한형 WAV

현재 파일 입력은 PDF, DOCX, PPTX, XLSX, CSV, TXT, MD, PNG, JPG/JPEG, WAV입니다. MP3/M4A는 미지원입니다. 확장자만 바꾸어 등록하지 마세요. 파일마다 필요한 처리 모델과 원문 검증이 끝나 `사용 가능` 상태여야 질문 근거로 쓸 수 있습니다.

WAV는 RIFF/WAVE의 비압축 PCM16, 모노 또는 스테레오, 표본율 16,000·22,050·24,000·44,100·48,000Hz, 재생 시간 1~120초, 파일 크기 25MiB 이하만 지원합니다. 이 범위를 벗어난 코덱·표본율·길이는 거부됩니다. WAV 처리에는 준비된 내부 ASR와 의미 분석 모델이 필요하며, 전사문과 시간 위치를 함께 확인합니다.

### Notebook별 모델과 추론 옵션

Notebook별 모델 선택이 우선합니다. 아직 별도 선택을 저장하지 않았다면 관리자가 저장한 정확한 Workspace 기본값을 표시합니다. 화면 조회만으로 저장하지 않으며, 모델 실행이 필요한 질문이나 Studio 생성을 실제로 명령할 때 그 선택을 Notebook에 확정합니다. 기본값이 없거나 현재 사용할 수 없으면 허용된 모델을 직접 선택합니다. 저장한 Notebook 모델이 사용 불가여도 다른 모델로 자동 대체하지 않습니다.

모델 변경은 자동 저장되며 다시 열어도 복원됩니다. 추론 옵션은 선택 사항입니다. 지원되는 연결에는 `낮음·보통·높음`을 표시합니다. `추론 선택 없음`이면 선택기를 표시하지 않고, `지원 정보 미확인`이어도 추론을 선택하지 않은 질문은 실행할 수 있습니다. 미선택은 옵션을 보내지 않는 상태이며 특정 추론 등급을 자동 지정하지 않습니다. 모델을 바꾸면 이전 모델의 추론 선택은 해제됩니다.

저장 중에는 실행을 기다립니다. 저장 실패·버전 충돌·응답 미확정은 `다시 조회`하여 현재 모델과 추론을 확인합니다. 다른 탭의 변경을 강제로 덮거나 질문을 자동 재전송하지 않습니다. 사용자가 직접 선택한 등록 모델 `auto`도 그대로 전달하며 Daon이 임의로 첫 후보나 다른 Provider로 바꾸지 않습니다. 잘못된 모델 ID와 지원 정보는 연결 설정에서 수정합니다.

### 질문과 이력

인사·감사·앱 도움말은 Source 없이도 정상 응답합니다. 사실 답변은 선택한 사용 가능한 Source에만 근거하며, Source가 없거나 관련 근거가 없으면 모델을 호출하지 않고 필요한 자료를 안내합니다. 인사에 사실 질문을 섞어도 근거 검사를 건너뛰지 않습니다. 일부 근거만 확인되면 원문 발췌와 부족한 자료를 구분하므로 질문 전체의 확정 답변으로 사용하지 마세요.

질문과 답변은 순서대로 누적되고 Notebook을 다시 열면 저장된 이력을 불러옵니다. 실패·취소·추가 인증 대기 기록도 이전 대화를 지우지 않습니다. 정상 완료 뒤에는 제출한 질문과 현재 입력이 정확히 같을 때만 입력창을 비웁니다. 처리 중 새로 쓴 내용이나 실패·결과 미확정·추가 인증 취소 때의 입력은 보존됩니다.

추가 인증은 현재 정책이 요구할 때만 진행합니다. 조직과 Workspace가 모두 추가 인증 없이 허용하면 별도 비밀번호 입력을 요구하지 않지만 현재 권한·목적지·마스킹·전송 범위 검사는 계속 적용됩니다.

### Studio 선택과 작업 확인

Studio를 선택하지 않은 일반 질문은 답변과 대화 이력만 만들고 Studio 생성을 시작하지 않습니다. 산출물은 유형과 설정을 직접 확인한 뒤 `생성`을 눌러 만듭니다. 표시한 Notebook 모델과 추론 선택이 생성 요청에도 적용됩니다. AI 재생성과 설정 변경은 새 작업으로 처리되며, 수동 편집은 입력한 내용과 사유로 별도 Version을 만듭니다.

규정·비교 대상·수치·관계 근거가 부족하면 필요한 자료를 안내하고 유효한 산출물을 꾸미지 않습니다. 생성 중 응답을 잃거나 대기 시간이 지나면 `처리 상태 확인`으로 기존 작업을 조회합니다. 접수 여부가 불명확한 상태에서 새 생성을 반복하지 않습니다. Source나 모델을 바꿔도 이전 작업의 접수 정보는 보존되며 늦게 온 결과가 새 화면을 덮지 않습니다.

### 화면 폭과 보조 패널

1920 화면은 자료·대화·Studio의 3면입니다. 1200 화면은 현재 작업할 2면을 선택하고 나머지를 Drawer로 엽니다. 보조 패널의 닫기 또는 Escape로 닫으면 현재 보이는 열기 버튼으로 초점이 돌아옵니다. 패널을 전환하거나 창 폭을 바꿔도 Source 선택·질문 초안·대화·모델 설정·Studio 편집 내용은 유지됩니다.
